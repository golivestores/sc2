每次被用户指出做错（"这个错了"/"原版不是这样"/"基础错误别再犯"等），**不能只静默修 bug**。必须按三层格式做根因复盘并在回复中明示：

1. **直接原因** — 具体代码/逻辑层面错在哪
2. **抽象教训** — 这次错跟之前哪些错是同一根因？为什么没归纳出规则？
3. **未来避免** — 工作流/检查清单要加哪条硬动作，让下次写代码时阻止这个错再发生

**Why**：用户 2026-05-27 反馈："34 没什么问题了 35 怎么滚动时一卡一卡的原版很流畅" → 紧接着说"思考错误原因 每次犯错都需如此"。背景：

- 034 已经被指出"setInterval 步进 → 应该 rAF 匀速"，我修了
- 紧接着 035 又写出 `.is-active` 离散切层 + scroll 事件驱动（同样的"离散 vs 连续"根因）
- 说明我把两次错当成"两个独立 bug 各自修"，没抽象出共同根因 → 必然反复犯

**How to apply**：

被指出错误时，回复结构必须包含三段：

```
## 直接原因
- 1-3 条具体代码/逻辑错（不是症状）

## 抽象出来的错（更严重）
- 这次错跟最近 N 次错的共同根因
- memory 里已有的哪条规则没用上 / 用反了
- 工作流哪一步该做没做（典型：写前没 mirror 实测、写后没数值验收）

## 未来怎么避免
- 一条可执行的硬动作（不是"以后多注意"这种空话）
- 写进哪个 memory / 哪个 checklist
```

如果"抽象出来的错"找不出共同根因或工作流缺失，说明反思没做到位，回头再想 — 直接错只到第一层就停笔是允许 ritual 退化的开始。

**触发条件**：
- 用户说"错了" / "不对" / "原版不是这样" / "基础错误" / "想想为什么"
- 用户两次以上指出同类问题（即使措辞不同）
- 自己回头看代码发现刚改完的东西犯了 30 分钟前刚被纠正过的同类错

**不触发**：
- 用户只是补充信息 / 改需求，不是说我做错
- 单纯的 typo / 拼写错（这种直接改就行，没复盘价值）
