After `python scrape-url.py URL NNN-slug "Title"` on a Nuxt 3 SPA, the auto-rebuild + headless verify will report a render but the page will be visually broken (404s on CSS/images, "PAGE NOT FOUND" route, etc.). The auto `_nuxt/` root-copy step gets you part of the way but five more things typically need manual fix-up:

1. **CSS chunks not in HTML** — the inline `<link rel="stylesheet">` only covers a few base CSS files. Route-specific CSS (default.HASH.css, index.HASH.css, error-500.HASH.css, etc.) is loaded by JS at runtime and not picked up by scraper.
   Fix: grep `entry.HASH.js` for `"\.\/[A-Za-z0-9_.-]+\.[a-f0-9]{8}\.css"` to find all referenced CSS, batch-fetch the missing ones into both `assets/<host>/_nuxt/` and `_nuxt/`.

2. **Asset folders (`images/`, `fonts/`)** are downloaded under `assets/<host>/` but CSS references them as `url(../images/...)` relative to its own location. Copy `assets/<host>/{images,fonts,audio,video}/` to mirror root so paths resolve regardless of which CSS copy is loaded.

3. **`<img src="/images/...">` and CSS `url(/images/...)` with leading slash**. Path shim only hooks fetch/XHR — not image src or CSS url(). Rewrite all JS/CSS source files: `"/images/X" → "./images/X"`, `url(/images/X) → url(./images/X)`. Same for `/fonts/`, `/audio/`, `/video/`.

4. **Nuxt history.replaceState rewrites `location.href` to `/`** after hydration, breaking all relative paths in subsequent runtime-set `<img>` sources. Inject `<base href="/designs/NNN-slug/">` right after `<head>` opening — this locks the relative-URL base regardless of history changes. Use the absolute server path so it works no matter where pushState moves location.

5. **Lazy-loaded images** referenced at scroll-trigger time, not as string literals. After step 4, do a headless scroll-through and capture all 4xx responses with URL containing `/designs/NNN-slug/images/`, then batch-fetch their live equivalents from `https://<host>/<rel-path>`.

6. **i18n locale router redirects to a root-absolute `/en` (or `/pt`) and escapes the mirror dir** — page renders the http.server "Error response" 404 page instead of the site. Symptom: headless verify reports `title: 'Error response'`, `body innerText length ~119` ("Error response / Error code: 404 / Message: File not found."), 0 imgs, 0 canvases, and a `framenavigated` to `http://127.0.0.1:PORT/en` (note: **root**-absolute, not under `/designs/NNN/`). Even the scrape's own auto-verify shows this. **Why**: `@nuxtjs/i18n` middleware matches `location.pathname`; the mirror runs at `/designs/NNN-slug/index.html` which matches no locale route, so the middleware does `navigateTo('/en')` built from `app.baseURL='/'` → a real top-level navigation to root `/en` → http.server 404. `<base href>` does NOT help (it only affects relative-URL resolution, not `location.pathname` matching). This is the Nuxt-i18n analog of `scrape-pitfalls.md` #4 (React Router path mismatch) and the React Router v7 recipe step 4. **Fix**: inject, right after the `<base href>` and *before* the path-shim script, a one-liner that rewrites pathname to the SSR'd locale route so Nuxt hydrates in place:
   ```html
   <base href="/designs/NNN-slug/">
   <script>try{history.replaceState(history.state,'','/en'+location.search+location.hash);}catch(e){}</script>
   ```
   Use the **actual SSR'd route** (`/en` for `phive.pt/en`) — rewriting to `/` would just trigger the locale redirect to `/en` again. Verify signal: navigation to `/en` stops, `scrollHeight` matches live (phive: mirror 15555 == live 15555), WebGL hero canvas sizes up (e.g. 2880×1800) instead of staying 300×150.

Don't generalize step 1-6 into scrape-url.py defaults blindly — each is mildly site-specific (CSS hash patterns, image folder names, base href path, locale route). But for any Nuxt 3 SPA mirror, expect 1-5; for an i18n Nuxt site, also expect 6.

Sites seen with this pattern: 008-donmolinico (partial — got step 4 issue but stopped at "reference-only"), 009-obsidianassembly (full 5-step recipe applied successfully), 034-phive (Burocratik Nuxt 3 + Three.js WebGPU + GSAP + Sanity CMS — needed steps 1/2/4 + the new i18n step 6; Sanity images/audio + DigitalOcean-Spaces club videos stay live-CDN, ~8 imgs + some menu/footer text don't populate offline, same headless-CMS limit as 030-hut8 / 031-serverobotics).

## 2026-06-16 additions (037-moblinks — Nuxt 3 SPA + Three.js WebGPU/Draco + GSAP + Shopify "Savory" headless commerce)

This site is **prerendered SSG** (not `ssr:false`) — the HTML is real homepage markup (title "Moblinks", `_vercel/image.HASH` optimized variants baked into `<img srcset>`/inline CSS), `window.__NUXT__` is null. It renders a 500 page only **after hydration**. Recipe steps 1 (11 runtime CSS chunks: AppFooter/AppNoise/Konami/Page/Slider/_slug_×2/error-404/error-500/index/products), 2 (copy `static/` to root), 3 (`"/static/`→`"./static/` in JS, `url(/static/`→`url(../static/` in CSS), 4 (base href) all applied. Five MORE Nuxt-specific traps, each newly documented:

**7. The 500 is a route-gated loader-store crash, not a missing asset.** Symptom: title "500 - Internal Server Error | Nuxt", body text "Cannot read properties of undefined (reading 'scale')", canvas list empty `[]` (vs 3 on live), yet **"ASSETLOADER: LOADED" still logs**. Root cause: a Pinia loader store computes `ready = computed(() => route.name==="index" ? (logoReady && heroReady && taglineLogoReady) : true)`. The mirror runs at `/designs/NNN/index.html` → Vue Router can't match the `index` route → `route.name!=="index"` → **`ready` short-circuits to `true` immediately** → an `{immediate:true}` watcher fires the intro GSAP timeline (`gsap.context` with `forceMode`) which reads `logoModelRef.value.scale` before the async GLB has loaded → TypeError → Nuxt swaps to its 500 page. This is the Nuxt analog of scrape-pitfalls #4 / step-6 i18n, but the gate is a **store computed on route.name**, not a router redirect. Diagnose by reading the caught error's stack: instrument the default error handler (grep `async function r(o){await i.callHook("app:error",o)` and prepend `console.error("X",(o&&o.stack)||o);`) since the error is swallowed into `payload.error`, never reaching `window.onerror`/`pageerror`. **Fix**: inject, right after `<base href>` and before the path-shim, an EARLY `history.replaceState` to `/` so the route resolves to `index` before the immediate watcher runs:
```html
<base href="/designs/NNN-slug/"><script>try{if(location.pathname!=="/")history.replaceState(history.state,"","/"+location.search+location.hash);}catch(e){}</script>
```
(Note: even though Nuxt itself later rewrites `location.pathname` to `/`, that happens too late — the `immediate` watcher already fired against the unresolved route. You must force `/` *before* Nuxt boots.)

**8. Forcing pathname to `/` BREAKS the path-shim's de-dup → doubled `/designs/NNN/designs/NNN/` prefixes.** The auto-injected shim computes `var __docDir = location.pathname.replace(/[^/]*$/,'')` to detect already-prefixed URLs. Once step 7 forces pathname to `/`, `__docDir` becomes `/` (length 1) so the "already prefixed" guard never triggers, and any absolute URL THREE's GLTFLoader/FileLoader resolves against the base href (e.g. `/designs/NNN/static/models/x.glb`) gets re-prefixed → `/designs/NNN/designs/NNN/static/...` 404. **Fix**: hardcode the shim — `var __docDir = '/designs/NNN-slug/';`. Then absolute mirror-path URLs pass through unchanged and root-absolute `/x` still becomes `./x`.

**9. Vercel image optimizer + extensionless `_vercel/image.HASH` files.** (a) The Nuxt-image provider builds `/_vercel/image?url=...&w=&q=` which 404s offline — patch the provider's `getImage` return (grep `{url:t+"?"+...({url:n,w:...})}`) to `{url:n}` so `<Image>`/`useImage()` emit the raw src. (b) `$img()`/`useImage()` normalizes a `./static/x` arg to root-absolute `/static/x` BEFORE the provider runs, so the raw src still 404s at server root for client-set backgrounds (e.g. `PatternBackground` sets `--var:url(useImage()("./static/images/puzzle-pattern.png"))`). Fix by patching that literal to a **deploy-absolute** `/designs/NNN/static/...` (survives the leading-slash normalize). (c) The scraper saves optimizer outputs as extensionless `assets/<host>/_vercel/image.<hash>`. AVIF/WebP still render in `<img>` (Chromium content-sniffs), but **SVG does NOT** — served as `application/octet-stream` by `python -m http.server`, `<img>` refuses it (security). Detect SVG-typed ones (`file` → "SVG"), `cp image.HASH image.HASH.svg`, and rewrite their `<img src/srcset>` refs to the `.svg` twin. (037: the footer's scattered jigsaw-pieces decoration was invisible until this — a textbook "renders + 0 broken-img-count but a whole decorative layer missing" that only the live A/B screenshot caught.)

**10. Nuxt app manifest 404 + hardcoded Vimeo video.** (a) Nuxt fetches `/_nuxt/builds/meta/<buildId>.json` (+ `/_nuxt/builds/latest.json`) for route rules; 404 there throws during hydration. `curl` both from live into root `_nuxt/builds/{meta,}/`. (b) Heavy-media sections may hardcode a signed Vimeo URL (`"video-src":"https://player.vimeo.com/progressive_redirect/playback/<id>/rendition/1080p/file.mp4?...&signature=..."`). `curl -L` it while the signature is fresh (302→CDN, ~80MB) into `static/videos/`, rewrite the URL to the local deploy-absolute path. **Verify true offline** by Playwright-routing `**/*` and aborting any non-127.0.0.1 host — a clean mirror leaves only the inherent backend (here Shopify Storefront GraphQL `<id>.myshopify.com` for cart creation; products themselves are prerendered so the page is 100% offline-renderable, only add-to-cart needs network). Dedup note: the local `*.mp4` are referenced as `./static/videos/` (root) only, so the `assets/<host>/static/videos/` copies are dead weight — delete them (saved 41MB).
