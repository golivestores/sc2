scrape-url.py only handles Nuxt with --nuxt-spa-fixup; Next.js App Router needs an analogous 6-step pass. Symptoms after raw scrape: 200+ 404s for /_next/static/chunks, /images/, /sequence/, plus a loader stuck at "99%" (frame-sequence pre-cacher waiting on missing JPGs).

**Recipe** (applied in c:/tmp/fix_017.py as the canonical template — copy and adapt for each site):

1. **Inject `<base href="/designs/NNN-slug/">` after `<head>`.** Makes all subsequent rewrites resolve via base — no need for `./` prefixes.

2. **Rewrite absolute → base-relative in index.html.** For every site-local prefix (`images`, `metadata`, `videos`, `sequence`, `_next`, plus whatever else `grep -ohE '"/[a-z]+/' index.html | sort -u` reveals): replace all of `\"/X/`, `"/X/`, `'/X/`, `&#x27;/X/`, `url(/X/` with the slash-less form `\"X/` / `"X/` etc. RSC flight payloads use the escaped `\"` form, inline styles use `'` and `&#x27;`.

3. **Patch webpack publicPath in `_next/static/chunks/webpack-*.js`.** Find `.p="/_next/"` and change to `.p="_next/"`. Webpack `<script>` injection bypasses `<base>` (URL constructed manually), so this MUST be relative.

4. **Patch absolute paths inside JS chunks.** Same prefixes as step 2, but only `"X"` and `'X'` quoting forms. Don't forget `_next` — chunks contain hard-coded `src:"/_next/static/media/footer-X.png"` from Image static imports.

5. **Flip `unoptimized:!1` → `unoptimized:!0`** in the chunk that contains `path:"/_next/image"` (Next.js Image config). The optimizer endpoint doesn't exist statically; this makes `<Image>` use raw `src` directly.

6. **Copy real asset trees up one level.** For every prefix in step 2 that exists under `assets/<host>/`: `shutil.copytree(assets/host/X, NNN-slug/X)`. With `<base href>` they're now reachable as `X/...`. **Also copy `assets/<host>/_next/static/{css,media}` into root `_next/static/`** — scrape often leaves root `_next/` with only `chunks/`. And copy `assets/<host>/_next/image.*` into root `_next/` — Next.js srcSets reference those as `_next/image.HASH` filenames (the optimizer cache), not as `?url=…&w=…` query strings, so `unoptimized:!0` alone won't save you if the HTML already baked the hashed paths.

**Out-of-band**: frame sequences (e.g. `sequence/16x9_281/standard/*.jpg`) aren't in the asset extraction — they're discovered at runtime by JS. Scrape them with a separate parallel-fetch loop (12 threads ≈ 150s for 281 frames). Standard quality (1080p) is enough for the navigator iframe; skip the high-res tier unless asked.

**Residual 404s that are OK to leave**: RSC prefetches for sibling routes like `/pricing?_rsc=…` `/blog?_rsc=…` — Next.js auto-prefetches Link targets that don't exist in a single-page mirror.

**SW gotcha**: If a Next.js mirror registers a service worker (e.g. fromanother.love → `sw.js`), the SW can intercept fetches and rewrite relative asset paths back to root-absolute (`/icons/...` instead of `./icons/...`). When debugging mysterious root-absolute 404s that don't appear in any chunk grep, disable the SW (`context = browser.new_context(service_workers="block")`) — if the 404s vanish, the SW was the culprit. For a clean local demo, either keep SW disabled at viewing time or strip the SW registration call from the chunk that calls `navigator.serviceWorker.register`.

**Heavy-asset preloaders that hang**: Sites that gate the hero behind a numeric `%` preloader waiting on Mux HLS / large videos will sit at ~35–50% forever offline. For a clean `preview.png`, force-hide the fixed full-viewport overlay containing `%` text via `page.evaluate`, then wait ~5s for the underlying scene to render. **To actually unblock the preloader for real use** (so the page becomes interactive, not just screenshotted), the fix is three steps deep:
1. Rewrite `https://stream.mux.com/${id}.m3u8` → `missing-stream-mux/${id}.dead` in both chunks AND in `index.html` RSC payload. `.dead` (not `.m3u8`) is critical so the page chunk's `if (/\.m3u8/.test(e) || e.includes("m3u8"))` detection falls through to the native `t.src=e` branch and the 404 triggers `<video>` onerror.
2. In the `ReactPlayer` chunk (the one with `hlsConfig` + `attachMedia`), replace `Hls.isSupported()` → `!1`. ReactPlayer ignores src suffix and unconditionally calls `attachMedia` whenever Hls is supported — must force the native fallback.
3. In the preloader-store chunk (zustand store with `assetsRequests`/`cpmRegister`/`assetsProgress`), short-circuit `n>=r.assetsRequests&&n<r.cpmRegister` → `false&&...`. This early-return path updates only `assetsLoadTo` and skips `assetsProgress`, so even when every asset has unregistered, the progress bar can stay frozen at a partial value because `cpmRegister` (incremented per ReactPlayer mount) is out of sync.

## 2026-06-16 additions (036-maddys2025 — Next.js App Router + Turbopack + GSAP ScrollTrigger)

**A. The patched root `_next/` tree is dead weight if the HTML still loads chunks from `assets/<host>/_next/`.** scrape-url.py rewrote every `<script src>`/`<link>`/modulepreload in index.html to the host-grouped path `assets/maddys2025.ripplear.live/_next/static/chunks/...` (relative, so they DO load), and *separately* copied a root `_next/` tree (the "runtime-resolved root path" copy). The recipe's mental model — "HTML uses root-absolute `/_next/`, patch root tree" — was only half right: a few root-absolute `/_next/` refs existed AND base href resolved them to the root tree, but the **bulk of the chunks loaded from `assets/<host>/_next/` which I never patched**. Result after patching only root `_next/`: chunks loaded fine but ran *unpatched* code (image loader still built `/_next/image?url=`, config `path` still root-absolute). Symptom that exposes it: the served file (`curl .../​_next/static/chunks/6648-*.js`) shows your patch, but the browser executes old behavior, and `grep` shows the `assets/<host>/` copy is unpatched. **Fix: unify onto one tree** — `index.html` replace `assets/<host>/_next/` → `_next/` (234 refs here), so everything loads from the single patched root tree (which already has all chunks/css/media + the `image.HASH` optimizer-cache files). Then base href resolves `_next/...` under `/designs/NNN/`. (Alternative: patch the `assets/<host>/_next/` tree instead — but unifying is cleaner.)

**B. Recursive chunk glob — `app/` subdir.** Page/layout chunks live in `_next/static/chunks/app/{page,layout}-<hash>.js`. A glob of `chunks/*.js` MISSES them, so their static-import image srcs (`{src:"/_next/static/media/highlight1.HASH.jpeg",...}`) and `/assets/` refs stay root-absolute. Always glob `chunks/**/*.js` recursive.

**C. Raw `_next/static/media/*.{jpeg,png}` are often NEVER downloaded** — scrape only grabbed the optimizer *outputs* (root `_next/image.HASH` cache files referenced by the SSR srcset). After a React #418 hydration mismatch (common, and present on the *live* site too), the client re-renders and the `<Image>` loader rebuilds `/_next/image?url=...&w=640&q=75` query URLs which don't exist statically. Flipping config `unoptimized:!1`→`!0` did NOT stop it here. **Robust fix:** (1) patch the default loader `X.path+"?url="+encodeURIComponent(src)+"&w="+w+"&q="+(q||75)` → `return src` (regex on var names) so every `<Image>` uses raw src; (2) make srcs relative (strip `"/_next/` → `"_next/`); (3) download the raw media from live (`/_next/static/media/<file>`, 200 OK) into the root media dir. Also fetch site-level `/assets/*.{png,svg,webp}` (CSS `url(../../../assets/X)` → mirror-root `assets/X`; one chunk had root-absolute `"/assets/eye-icon.png"` → strip to `"assets/`).

**D. GSAP ScrollTrigger stale-measurement → inject a `resize`-pump self-heal (NEW, reusable for ANY GSAP mirror).** A scroll-driven sticky/scrub element (here a rotating footer badge) lands off-center & undersized offline: the scrub maps scrollY→progress with start/end pixel positions measured *before* the fast local images settled the layout. `window.ScrollTrigger`/`window.gsap` are bundled (not global) so you can't call `ScrollTrigger.refresh()` directly — but ST registers a `resize` listener that calls refresh internally. **Fix:** inject (idempotent, `<!-- sc2-mirror-fix:start/end -->`) a script that `window.dispatchEvent(new Event('resize'))` on a pump (200/700/1500/3000/5000 ms after load), again after all `document.images` decode, AND debounced on the first ~6 scroll events (the self-heal — one refresh once the user scrolls and everything below the element is in its final state is what actually nails it). Verify by motion-sampling the element's `getBoundingClientRect()` [top,left,width] across scrollY on mirror vs live — the curves should match (here badge converged to [237,299,842] vs live [218,315,811]). Diagnosis signal: element present + loaded + `opacity:1` + correct DOM position when probed at the very bottom, but a *stable* horizontal/scale offset mid-scroll. Related to pitfall #9 (intro timeline not firing) but a distinct mechanism: scrub start/end mapping, not an unfired reveal.

## 2026-06-17 additions (042-redis — SELF-HOSTED Next.js 15 + Turbopack, NOT Vercel)

redis.agency is Next.js 15 + Turbopack + RSC but **self-hosted** (no Vercel, no `?dpl=` token, no buildId/deploymentId in HTML). Chunks are 16-hex contenthash names (`02afd00a3500012c.js`), `<script src>` rewritten by scraper to relative `assets/<host>/_next/static/chunks/X.js`. Symptom: mirror stuck on black intro loader, `window.next===undefined` (no hydration), bodyLen frozen at SSR shell (1753 vs live 3370). This is the clean variant of scrape-pitfalls #5.7/#6 — and it has a **one-line root-cause fix** that the Vercel `?dpl=` saga doesn't need.

**E. Turbopack `publicPath` is hardcoded `/_next/` → patch it to the scraper's relative tree.** The turbopack runtime (`turbopack-<hash>.js`) builds every chunk URL via `K(e)=\`${t}${e...}${r}\`` where `let t="/_next/"` (publicPath) and `r`=currentScript query suffix (empty when self-hosted, no `?dpl`). It detects "chunk already loaded" with `document.querySelectorAll(\`script[src="${t}"],script[src^="${t}?"],...\`)` — an **exact string match** against the `<script src>` attribute. Since `t`-built URL is root-absolute `/_next/static/chunks/X.js` but the HTML scripts are `assets/<host>/_next/static/chunks/X.js`, the selector misses → turbopack re-injects a fresh `<script src="/_next/...">` → that 404s at server root → the hydrate/chunk-load promise hangs → loader never clears. **Fix:** `let t="/_next/"` → `let t="assets/<host>/_next/"` (relative, so the built string EXACTLY equals the HTML `<script src>` literal → dedup detection passes → no re-fetch → hydration proceeds; and lazy chunks resolve via base href). Patch in BOTH the `assets/<host>/...` copy and the root `_next/...` copy of turbopack. This single patch + base href is what flips `window.next` from undefined→object.

**F. Full 042 recipe (works offline, 0 broken, verified by route-aborting all non-127.0.0.1):**
