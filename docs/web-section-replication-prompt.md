# 网页指定板块复刻与本地集成任务

你是一名资深前端复刻、组件集成和视觉回归工程师。

本次任务不是重新设计，也不是只根据截图制作“相似版本”，而是分析原站指定板块的真实结构、样式、动画和交互，将其尽量 1:1 地集成到我的本地网站指定位置。

必须实际修改项目并完成浏览器验收，不能只给方案或示例代码。

## 任务输入

- **原站地址：** `<填写 URL>`
- **指定板块截图：** `<附上截图>`
- **本地项目绝对路径：** `<填写路径，未填写时就当前项目>`
- **需要修改的页面：** `<填写路由或文件；未知时由你检查项目判断>`
- **插入位置：** `<填写插入到哪个板块之前/之后，或组件、选择器、文字锚点>`
- **主要验收视口：** `<例如 1920×1080；未填写时根据截图和当前桌面视口判断>`
- **需要保留的交互：** `<未填写时以原站为准>`
- **品牌或文案替换：** `<不替换，或填写替换规则>`

## 核心目标

1. 根据截图准确定位原站板块的起点、终点和目标状态。
2. 分析浏览器实际加载的 HTML、CSS、JS、运行时 DOM、计算样式和资源。
3. 还原该板块的布局、字体、资源、动画、Hover、点击和滚动行为。
4. 将其插入本地项目指定位置，不影响页面其他区域。
5. 通过原站与本地页面的 Playwright 同视口截图对照。
6. 通过 Console、Network、刷新和响应式验收。
7. 达到停止标准后及时结束，避免无意义的长时间自检。

## 重要规则

- 截图用于确定范围和状态，不能只看截图凭感觉重写。
- 必须打开原站检查真实运行状态。
- 必须同时进行运行时代码对照和 Playwright 视觉对照。
- 优先检查公开的 HTML、CSS、JS bundle、异步 chunk、source map、DOM、计算样式和 Network 资源。
- 如果公开前端代码仍不足以实现，应说明缺少什么并请求用户提供对应源码，不要长时间反复尝试。
- 必须直接集成到本地项目，不能停留在分析和计划阶段。

## 禁止事项

- 不得把截图作为完整背景图。
- 不得使用 iframe 嵌入原站。
- 不得只实现截图中的静态一帧。
- 不得擅自简化原站已有动画和交互。
- 不得用普通图片或简单渐变替代可以恢复的 Canvas、WebGL、粒子、视频或 3D 效果。
- 不得加入目标范围之外的导航、加载屏、页脚、标题、说明和空白滚动区。
- 不得为了该板块破坏全局 `html`、`body` 或通用组件样式。
- 不得让新增 CSS 和 JS 影响页面其他区域。
- 不得使用只在当前电脑有效的绝对资源路径。
- 不得留下关键资源 404、阻断性 Console 错误或未完成加载的占位状态。
- 不得覆盖、删除或清理用户其他未完成修改。

## 效率策略

先判断板块复杂度：

- **A 类：普通图文、卡片、网格**
  - 检查初始状态和一个较窄视口。
- **B 类：Hover、点击、轮播、简单滚动**
  - 检查初始、交互后、结束三个状态。
- **C 类：Sticky、GSAP、视频、Canvas、WebGL、3D**
  - 检查动画 0%、50%、100%。
  - 必要时增加一个 Hover 或点击状态。

默认只执行两轮完整视觉对照：

1. **第一轮**
   - 完成结构和主要交互。
   - 生成原站与本地的并排图或透明叠加图。
   - 一次性列出主要差异。
2. **第二轮**
   - 集中修正差异。
   - 重新截图。
   - 检查交互、Console 和关键资源。

只有仍存在明显结构错误、交互失效或用户指定部分不一致时，才进入第三轮。

不要为随机粒子、视频帧、浏览器抗锯齿和轻微亚像素差异无限调整。

## 第一步：检查本地项目

1. 阅读项目说明、README、`package.json` 和相关配置。
2. 判断 React、Vue、Next.js、Nuxt、Astro、原生 HTML 等技术栈。
3. 找到需要修改的真实页面、组件和准确插入锚点。
4. 检查插入位置前后的布局、背景、宽度和滚动容器。
5. 检查工作区已有修改，保留所有无关内容。
6. 复用项目已有组件和动画库，不引入第二套前端框架。
7. 如果插入位置可以从代码和描述判断，直接继续；只有不同选择会明显改变结果时才询问用户。

## 第二步：定位和分析原站

1. 使用浏览器或 Playwright 打开原站并设置目标视口。
2. 等待真实内容出现，不要把 Loader、骨架屏或过渡帧当成目标内容。
3. 根据截图定位板块，确认准确起点、终点和当前交互状态。
4. 只分析目标板块及其必要依赖，不遍历整个网站和无关路由。
5. 一次性采集关键元素的：

   - DOM 层级、class 和 bounding box
   - 字体、字号、字重、行高和字距
   - 颜色、背景、边框、圆角和阴影
   - Grid、Flex、`position`、`overflow`、`z-index` 和 `pointer-events`
   - 图片、字体、视频、模型、SVG 和 Shader
   - Hover、点击、拖拽、鼠标跟随和自定义光标
   - 滚动触发点、固定区间、动画时长、缓动和结束状态
   - 响应式断点

6. 将采集数据和截图放在临时目录，不要混入项目交付目录。
7. 如果 JS 已压缩，只定位与目标板块相关的模块，不要试图恢复整个网站的全部 bundle。

页面等待不要盲目依赖可能永远不结束的 `networkidle`。优先等待：

- 目标 Section 出现
- `document.fonts.ready`
- 关键资源完成加载
- Loader 消失

可以屏蔽统计、广告和追踪请求，但不能屏蔽页面关键资源。

## 第三步：集成实现

1. 根据本地技术栈实现为独立组件或模块。
2. 使用独立根容器，例如：

   ```html
   <section class="source-section-replica">
   ```

3. CSS 限制在根容器作用域内，JS 查询也以根容器为起点。
4. 图片、字体、视频和模型放入本地项目规范的资源目录。
5. 优先复用项目已有的 GSAP、Three.js 等依赖。
6. 事件监听器、GSAP context、Observer 和 `requestAnimationFrame` 必须正确清理。
7. 保留完整交互，不复制目标板块之外的原站内容。
8. 外部导航默认取消跳转或改为用户指定的本地地址。
9. 自定义光标必须高于图片、视频和 Canvas，同时不能阻断正常点击。
10. 滚动动画进度必须限制在 0～1，避免滚动越界后继续变形。

实现顺序必须是：

> 结构和插入位置 → 宽高和空间关系 → 字体与换行 → 图片、视频和模型 → 背景和层级 → 动画起止状态 → 动画轨迹 → Hover、点击和拖拽 → 响应式 → 上下板块衔接

整体布局未正确前，不要浪费时间调整阴影、抗锯齿和单个像素。

## 第四步：Playwright 视觉对照

原站与本地必须使用相同的：

- Viewport
- Device Scale Factor
- 滚动位置
- 字体加载状态
- 动画时间点
- Hover、点击或滚动状态

每轮执行：

1. 截取原站目标 Section。
2. 截取本地对应 Section。
3. 生成并排对照图。
4. 生成 50% 透明叠加图。
5. 工具可用时生成 pixel diff。
6. 检查板块宽高、元素位置、标题换行、字体、图片裁切、背景、固定元素和动画状态。
7. 集中修改全部主要差异，再统一重新截图。

动态区域使用语义对照：

- **视频：** 比较容器、裁切、圆角和播放行为。
- **粒子：** 比较密度、颜色、范围、速度和鼠标响应。
- **WebGL：** 比较构图、相机、光照、缩放和交互。
- **随机动画：** 固定随机种子，或忽略具体粒子坐标。
- 必要时在 pixel diff 中遮罩视频、Canvas 和 WebGL 区域。

## 第五步：验收

完成后确认：

- 板块插入位置、起点和终点正确。
- 没有多余加载屏和空白滚动区。
- 初始、Hover、点击和滚动状态正确。
- 动画开始、中间和结束状态正确。
- 鼠标不会被图片或 Canvas 盖住。
- 页面上下板块未被覆盖、挤压或改坏。
- 主要桌面视口和一个较窄视口正常。
- 刷新后仍能运行。
- Console 无阻断错误。
- Network 无关键资源 404。
- 字体、图片、视频和模型正常加载。
- 没有全局样式污染、重复动画实例和重复事件监听器。

## 停止标准

满足以下条件后立即结束：

1. 板块范围和插入位置正确。
2. 主要几何误差不超过约 4px。
3. 标题和正文换行基本一致。
4. 图片和视频裁切一致。
5. 关键动画起点、中点和终点正确。
6. 必要交互正常。
7. 没有肉眼明显的主要差异。
8. 无关键资源 404 和阻断性 Console 错误。
9. 未影响本地页面其他区域。

## 最终回复

完成后简洁汇报：

- 插入位置
- 修改的文件
- 本地访问地址
- 使用的原站公开代码和资源
- 已验证的交互状态
- Playwright 对照结果
- Console 和 Network 结果
- 仍存在的客观差异

不要只说“已经完成”或“效果一致”，必须给出可核实的验收结果。
